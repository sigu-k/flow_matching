現在の flow_matching リポジトリで、既存の objective-reduction adaptive bin 実装を改良してください。

対象ファイル:
- examples/image/objective_reduction_bin_sampler.py
- examples/image/train_phase1_bin_objective_reduction.py

重要:
- 今回は新規実装ではなく、既に作成済みの train_phase1_bin_objective_reduction.py / objective_reduction_bin_sampler.py を編集する形にしてください。
- 既存の train_phase1_twophase.py、train_phase1_bin_adaptive.py、train_phase1_bin_loss_aware.py など他の実験コードは基本的に触らないでください。
- 既存実験の checkpoint / W&B logging / sampler 実装を壊さないでください。

目的:
現在の objective-reduction 版では、sampler probability の変化幅が非常に小さく、reward がノイズに埋もれているように見える。
そこで、以下を導入して reward 推定を安定化し、かつ probability の変化幅を大きくできるようにする。

導入するもの:
1. sampler_eval_batches = 4
2. fixed eval samples + fixed eval noise
3. delta queue Q
4. selected evaluation subset S
5. reward_scale
6. temperature default を 0.5 に変更

============================================================
1. fixed eval samples / fixed eval noise
============================================================

reward 評価には、現在の training batch ではなく、固定 eval set を使うようにしてください。

仕様:
- 訓練開始前に dataloader から sampler_eval_batches 個の batch を取り出す。
- default sampler_eval_batches = 4。
- batch size 64 なら、合計256枚の固定 eval samples になる。
- eval samples は [-1,1] scale に変換して device に置く。
- eval noise は eval samples と同じ shape で torch.randn_like により一度だけ作成し、固定する。
- reward eval では毎回この fixed eval samples/noise を使う。
- training batch は従来どおり dataloader から来る現在の batch を使う。
- fixed eval set は reward 測定専用であり、training loss には使わない。

CLI:
--sampler-eval-batches default 4

W&B config:
sampler_eval_batches を追加。

============================================================
2. eval_fm_loss_at_bin_centers の拡張
============================================================

現在の eval_fm_loss_at_bin_centers が 1 batch の samples/noise を受ける形なら、fixed eval set 複数 batch に対応してください。

期待する返り値:
- bin_losses: shape [K]
  各 bin center tau_j における fixed eval set 全体平均 FM loss

仕様:
- torch.no_grad() で実行
- eval times は bin centers:
  tau_j = (j + 0.5) / K
- sampler_eval_batches=4 なら、4 batch それぞれで各 tau_j の loss を計算し、batch方向に平均する。
- raw_model を使う。EMA評価ではなく raw UNet を使う。
- repo の forward API に合わせる:
  pred = model(ps.x_t, t_eval, extra={})
  など既存実装に合わせてください。

============================================================
3. delta queue Q
============================================================

sampler update ごとに、評価時刻ごとの loss reduction vector を保存してください。

before_losses: shape [K]
after_losses: shape [K]

delta:
delta_j = before_losses[j] - after_losses[j]

delta_queue に過去 queue_size 回ぶん保存する。

CLI:
--queue-size default 20

sampler state:
- delta_queue
- queue_size
を checkpoint 保存・復元対象に追加。

W&B logging:
- sampler/delta_0 ... sampler/delta_9
- sampler/queue_len
- sampler/queue_size

============================================================
4. selected evaluation subset S
============================================================

reward は常に10個すべての評価時刻を平均するのではなく、queue を使って signal の強い評価時刻 subset S を選んで計算してください。

CLI:
--selected-eval-count default 3
--selection-method default "snr_topk"

selection_method = snr_topk の仕様:
delta_queue を tensor [Q, K] とする。

各評価時刻 j について:
mean_j = mean(delta_queue[:, j])
std_j = std(delta_queue[:, j])
score_j = abs(mean_j) / (std_j + eps)

score が高い top selected_eval_count 個の index を selected_eval_indices とする。

ただし queue の長さが 2 未満の場合は、まだ std が安定しないため、全 eval times を使って reward を計算してください。
この場合 selected_eval_indices は all indices として扱ってよいです。

reward 計算:
selected indices S に対して、

selected_delta_mean = mean(before_losses[S] - after_losses[S])
selected_before_mean = mean(before_losses[S])

relative_reward = selected_delta_mean / (selected_before_mean + eps)

この relative_reward を bin reward として使う。

W&B logging:
- sampler/selection_score_0 ... sampler/selection_score_9
- sampler/selected_eval_idx_0 ... sampler/selected_eval_idx_{N-1}
- sampler/selected_eval_time_0 ... sampler/selected_eval_time_{N-1}
- sampler/selected_eval_count
- sampler/selection_method

selected_eval_count=3 なら idx/time は3個出す。
queue不足で all を使った場合も、少なくとも selected_eval_count 用のキーは出し、追加で sampler/using_all_eval_times = 1 をログしてください。
通常時は sampler/using_all_eval_times = 0。

============================================================
5. reward_scale と probability の変更
============================================================

probability の変化幅を大きくできるように reward_scale を導入してください。

CLI:
--reward-scale default 100.0

temperature default:
--temperature default 0.5

probability 作成:
scaled_reward_ema = reward_scale * reward_ema
p_reward = softmax(scaled_reward_ema / temperature)
probs = (1 - uniform_mix) * p_reward + uniform_mix / K

uniform_mix default は既存どおり 0.1 でよい。

W&B logging:
- sampler/reward_scale
- sampler/scaled_reward_ema_0 ... sampler/scaled_reward_ema_9

W&B config:
- reward_scale
- temperature
- uniform_mix

============================================================
6. round-robin と reward update は維持
============================================================

既存の round-robin forced exploration は維持してください。

sampler update step:
- round-robin で training bin を強制選択
- その bin で training t をサンプル
- fixed eval set で before_losses を計算
- training batch で UNet を1 step更新
- fixed eval set で after_losses を計算
- selected S 上の relative_reward を計算
- 選ばれた training bin の reward_ema だけ更新
- reward_ema から probs を更新
- round_robin_idx を進める

通常 step:
- warmup 中は一様 sampling
- warmup 後は probs に従って bin sampling

warmup 中も sampler update / reward_ema update は行ってよい。
sampling は必ず一様にしてください。

============================================================
7. importance weighting は維持
============================================================

既存の partial importance weighting は維持してください。

importance_weight = (1 / (K * q_selected)) ** importance_gamma

default:
importance_gamma = 0.5

注意:
- training loss にだけ importance_weight を掛ける。
- reward eval loss には importance_weight を掛けない。
- warmup中に一様 q_selected=1/K の場合、importance_weight は1になるはず。

W&B logging は既存に加えて維持:
- sampler/importance_weight
- sampler/q_selected
- sampler/base_train_loss
- sampler/weighted_train_loss
- train/base_loss
- train/loss
